1. Justificación y Contexto Tecnológico: HCE vs. Android Beam

En el desarrollo moderno sobre el ecosistema Android, muchas aplicaciones académicas o proyectos legados intentaban utilizar Android Beam (basado en P2P NDEF Push con SNEP/LLCP). Sin embargo, Android Beam fue marcado como obsoleto en Android 10 (API 29) y eliminado definitivamente a partir de Android 14 (API 34) debido a su inestabilidad y falta de soporte en chipsets modernos.

Decisión de Arquitectura en RedSocialNFC: Se implementó la arquitectura oficial recomendada por Google para producción: Host-based Card Emulation (HCE) mediante la API HostApduService en combinación con Reader Mode (NfcAdapter.enableReaderMode) y fallback a etiquetas físicas NDEF.

Dispositivo Emisor (Tarjeta Inteligente Virtual)

El dispositivo emula una tarjeta inteligente sin requerir un elemento seguro (Secure Element) por hardware. El servicio NfcHandshakeService atiende comandos APDU ISO 7816-4 en segundo plano incluso con la pantalla encendida fuera de la app.

Dispositivo Receptor (Lector NFC de Alta Velocidad)

Al abrir la interfaz de vinculación o detección en Local, la app activa enableReaderMode con banderas FLAG_READER_NFC_A y FLAG_READER_SKIP_NDEF_CHECK, ejecutando el intercambio en milisegundos sin disparar los diálogos molestos del sistema operativo.

2. Protocolo de Comunicación APDU ISO 7816-4

Para asegurar que dos teléfonos con Local se reconozcan mutuamente de forma unívoca, se definió un Application Identifier (AID) propietario en el rango ISO 7816-4 de categoría F (Privado/Propietario):

AID Propietario Local: F0 01 02 03 04 05 06 (7 bytes)

Estructura del Paquete de Comando (Command APDU):

Campo Byte(s) Hex Significado / Función
CLA 0x00 Clase de comando estándar ISO 7816-4
INS 0xA4 Instrucción SELECT FILE / APPLICATION
P1 0x04 Selección directa por nombre de aplicación (DF Name / AID)
P2 0x00 Primera coincidencia / sin opciones adicionales
Lc 0x07 Longitud de los datos entrantes (7 bytes del AID)
Data F0 01 02 03 04 05 06 Identificador de la aplicación RedSocialNFC (Local)
Le 0x00 Longitud máxima esperada en la respuesta (256 bytes)

Estructura del Paquete de Respuesta (Response APDU):

El dispositivo emulador responde con la carga útil serializada en formato JSON UTF-8 concatenada con los dos bytes de estado (Status Word) SW1 = 0x90, SW2 = 0x00 (operación completada exitosamente): 

// Carga útil transmitida en el APDU Response de RedSocialNFC:
{
  "app": "RedSocialNFC",
  "version": 1,
  "handle": "@Luis",
  "nombre": "Luizx",
  "nfcUuid": "4e79b88d-75fb-4395-950c-d40b9557fa67",
  "avatarUri": "content://com.example.redsocialnfc.fileprovider/...",
  "timestamp": 1732700800000
} + [0x90, 0x00]

3. Implementación Paso a Paso en el Código Fuente

3.1. Registro del Servicio en AndroidManifest.xml

Para que el sistema Android reconozca el servicio de emulación de tarjeta, se configuró el permiso BIND_NFC_SERVICE y la acción del intent-filter HOST_APDU_SERVICE: 

<!-- AndroidManifest.xml -->
<uses-permission android:name="android.permission.NFC" />
<uses-permission android:name="android.permission.VIBRATE" />
<uses-feature android:name="android.hardware.nfc" android:required="false" />

<service
    android:name=".nfc.NfcHandshakeService"
    android:exported="true"
    android:permission="android.permission.BIND_NFC_SERVICE">
    <intent-filter>
        <action android:name="android.nfc.cardemulation.action.HOST_APDU_SERVICE" />
    </intent-filter>
    <meta-data
        android:name="android.nfc.cardemulation.host_apdu_service"
        android:resource="@xml/apduservice" />
</service>

3.3. Servicio de Emulación: NfcHandshakeService.kt

Hereda de HostApduService. Cuando otro teléfono en Reader Mode realiza un toque NFC, Android invoca processCommandApdu(). El servicio valida que el comando sea un SELECT AID para F0010203040506, extrae la identidad del usuario actual desde SessionManager y devuelve el payload firmado con 0x90 0x00: 

class NfcHandshakeService : HostApduService() {
    override fun processCommandApdu(commandApdu: ByteArray?, extras: Bundle?): ByteArray {
        if (commandApdu == null) return NfcProtocol.SW_UNKNOWN

        if (NfcProtocol.isSelectAidCommand(commandApdu)) {
            val session = SessionManager(applicationContext)
            val json = NfcProtocol.crearPayloadJson(
                handle = session.getRealHandle(),
                nombre = session.getDisplayName(),
                nfcUuid = session.obtenerOGenerarDeviceNfcUuid(),
                avatarUri = session.getAvatarUri()
            )
            val bytes = json.toByteArray(Charsets.UTF_8)
            val response = ByteArray(bytes.size + NfcProtocol.SW_SUCCESS.size)
            System.arraycopy(bytes, 0, response, 0, bytes.size)
            System.arraycopy(NfcProtocol.SW_SUCCESS, 0, response, bytes.size, 2)
            return response
        }
        return NfcProtocol.SW_UNKNOWN
    }
    override fun onDeactivated(reason: Int) { /* Desconexión NFC */ }
}

4. Experiencia de Usuario (UI) y Vinculación en Tiempo Real

La integración de NFC cuenta con componentes visuales de alta fidelidad desarrollados en Jetpack Compose Material 3:

  • Diálogo de Radar NFC (DialogNfcHandshake.kt): Presenta una animación continua de ondas concéntricas (efecto sonar/radar con rememberInfiniteTransition) que transmite al usuario que el sensor físico se encuentra emitiendo y a la escucha.
  • Detección de Estado de Hardware: Si el usuario tiene el NFC apagado en los ajustes de Android, el diálogo lo detecta automáticamente mostrando un banner con botón de acción directo: "Activar NFC en Ajustes" (lanzando Settings.ACTION_NFC_SETTINGS).
  • Simulador de Handshake Integrado para Pruebas y Emuladores: Dado que los emuladores de Android Studio de escritorio no poseen chip NFC físico, se diseñó una pestaña dedicada de Simulación de Handshake. Esta pestaña ejecuta exactamente el mismo pipeline criptográfico de serialización y deserialización JSON de NfcProtocol, permitiendo al profesor o evaluador probar la vinculación con usuarios preset (@Carlos_Dev, @Valeria_UX, @Profe_JC) o cualquier usuario personalizado en un solo clic.
  • Inserción Automática en Room Database: Al concretarse el toque NFC (físico o simulado), el contacto se persiste de forma reactiva en la tabla amigos mediante AmigoDao.insertar(nuevoAmigo) y se redirige automáticamente al chat directo.
