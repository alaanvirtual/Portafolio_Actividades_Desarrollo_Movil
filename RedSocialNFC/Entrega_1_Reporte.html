1. Resumen Ejecutivo

El presente documento describe los resultados técnicos y de diseño implementados para la Entrega 1 de la aplicación móvil RedSocialNFC. El objetivo principal de esta fase es establecer la base arquitectónica del sistema, la gestión de doble identidad (identidad real y seudónimo anónimo) y el registro criptográfico de hardware para comunicación por proximidad NFC, en estricto apego a las directrices de Material Design 3 (Jetpack Compose) y la paleta temática Digital Alchemy.

3. Arquitectura y Persistencia de Datos

Para garantizar el funcionamiento sin conexión a internet y mantener la coherencia con el temario del curso, se implementó un esquema de doble almacenamiento local:

1. Base de Datos SQLite Local (Room Database): Almacena de forma estructurada los registros en la tabla usuarios, incluyendo credenciales, handles y UUIDs vinculados.
2. SharedPreferences (SessionManager): Gestiona la persistencia de la sesión activa para que el usuario no deba reautenticarse al reiniciar la aplicación, conservando el UUID de hardware asignado.

Estructura de la Entidad de Datos (Room)

@Entity(tableName = "usuarios")
data class Usuario(
    @PrimaryKey(autoGenerate = true) val id: Int = 0,
    val email: String,
    val passwordHash: String,
    val realHandle: String,        // RF-02: @handle real único
    val anonHandle: String,        // RF-03: Pseudónimo inalterable (@Anonimo_XX)
    val nfcUuid: String,           // RF-04: UUID privado para antena NFC
    val fechaRegistro: Long = System.currentTimeMillis()
)

4. Diseño Visual: Paleta "Digital Alchemy"

La aplicación adopta una identidad visual basada en la temática místico-criptográfica Digital Alchemy mediante un esquema de colores oscuros con acentos neón:

  • Dark Background (#0B0813): Fondo principal ultra oscuro de alta inmersión.
  • Neon Magenta (#FF007F): Acento principal para la identidad real de 1er grado (conexiones directas por NFC).
  • Electric Violet (#8A2BE2): Acento secundario para elementos de 2do grado y seudónimos anónimos.
  • Neon Cyan (#00E5FF): Distintivo de hardware, criptografía y estado de la antena NFC.

5. Flujo Operativo de la Aplicación

  1. Inicio del Sistema: MainActivity consulta a SessionManager si existe una sesión abierta. Si no existe, presenta AuthScreen.
  2. Registro de Identidad: El usuario ingresa su correo, contraseña y su handle deseado. El sistema valida en tiempo real la no duplicidad, genera en memoria su seudónimo inalterable y su UUID de hardware.
  3. Persistencia y Navegación: Se guardan los datos en Room y SharedPreferences, redirigiendo al usuario a PerfilScreen.
  4. Visor de Identidad: Muestra de forma clara la separación entre la identidad real de 1er grado y la anónima de 2do grado, permitiendo cerrar sesión en cualquier momento.
